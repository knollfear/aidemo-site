You Had One Job

Getting more from AI by doing less with AI.

scroll ↓

This started as a chore, not an architecture.

I wanted a website
for my kids.

That’s the whole origin story. What made it interesting was the list of things I wasn’t willing to sign up for.

  • ✓Somewhere my kids can publish their own stuff
  • ✓Kid writes a sentence → it’s on the site. No ceremony, no ticket, no waiting on Dad
  • ✓Me as content police — that job I’ll happily take
  • ✗Me as Head of IT. Or IT shadow.
  • ✗A monthly bill with a growth curve
  • ✗A CMS to patch, a database to back up, a plugin that breaks on January 19, 2038
  • ✓An AI angle — and I’ll be honest about why: my future employability apparently depends on how well I can convince an AI that I understand AI
  • ✗An AI that gets creative with the budget. Or the facts.

Cheap, boring, kid-proof — with exactly enough AI in it to be a period piece. The folder part will still work in 2038. Ask me about the AI part then.

The less you do, the more you do.

Most of an “AI” pipeline
isn’t AI.

This is a system that turns an email — “dear website, I got a new bike, here’s a photo” — into a live website update, in about two minutes.

It has exactly one seam of AI. Everything else is plain, boring, trustworthy code. That’s not a compromise. That’s the design.

First, the boring part. It’s load-bearing.

The whole website
is a folder.

No database. No app. No server humming somewhere. This site is a folder of text files — and every idea in this talk is just a rule about who is allowed to change that folder, and when.

📁 Git

An undo button with a memory. Every change to the folder is saved as a labeled snapshot — who, what, when — forever. Track-changes, but for a folder.

🐙 GitHub

That folder, online, where changes get proposed rather than just made. A “pull request” is a suggested edit, sitting in a queue. “Here’s my change — okay?”

🌐 GitHub Pages

Free hosting. GitHub takes the folder and hands it to anyone who visits. Nothing to run, nothing to patch, nothing to pay. This page is that folder.

⚙️ GitHub Actions

A robot that watches the folder. An approved change lands, it rebuilds the site and publishes — about ninety seconds, hands off. Same checklist every time, or it fails loudly.

Why spend two minutes on that? Because it’s the entire safety story.

A dumb folder beats
a clever robot.

All four of those pieces are boring on purpose. Boring is exactly what makes it safe to let an AI near a kid’s website at all.

📁

A page that’s a file

  • Somebody read it before it went up
  • Every version is on the record — yesterday’s is one click away
  • Nothing runs when a visitor arrives, so nothing breaks at 2 a.m.
  • Costs $0, and outlives my interest in it
🤖

A page the AI serves

  • Written fresh for each visitor — nobody read it first
  • No version to roll back to; it just said something different
  • Down when the API is down
  • A bill, and a thing to babysit

So the AI never touches the live site. It proposes a change to a folder, a human says yes, and a robot ships it. That’s the whole trick.

Old man yells at cloud.

👴

That’s how the web used to work — and we liked it!

☁️ 487 settings. one of them ruins you.

It was never the cloud.

I love the cloud. This site is on it, for free. What I don’t need is nginx, in a bespoke Docker container, on a medium EC2 instance, in a VPC I hand-designed, in front of an Aurora database. That isn’t the cloud’s promise — that’s a datacenter I’m renting, with 487 new ways to be wrong.

GitHub Pages is the promise: I bring files, somebody else already made every other decision and lived with it. Give me five rock-solid architectures that cover 99% of the web and let me point at one. Fewer knobs, fewer ways to be catastrophically wrong — the same bet I’m making with the AI.

Do you see how much I’m not doing?

I don’t wear a watch anymore. My phone tells the time.

The everything-device trap.

The LLM is the smartphone of your stack. It can do almost anything — a little. Which is exactly why you’re tempted to let it absorb every job.

⌛

A watch

Does one thing. Glanceable, cheap, never asks you to log in, never hallucinates the time.

  • parse an address
  • validate a slug
  • move a file, open a PR
📱

A phone

Also tells the time — while being a slot machine, a camera, and forty notifications.

  • understand “I got a new bike”
  • …and that’s it.

Don’t make a load-bearing clock out of a slot machine. Use a watch for the watch jobs.

Do less. Not nothing. You gotta do something.

Do less — not nothing.

The trap has two walls. Teams go all-AI, get burned, then swing to all-rules and rebuild a brittle regex that chokes on the first kid who spells “dinosaur” wrong.

Turning a messy human sentence into structured intent is a real job that only the model does well. So you don’t do nothing with AI. You do less. Land the plane in the narrow middle.

When life gives you lemons, say ‘forget the lemons’ and bail.

Bail to a human.

The safety model isn’t “trust the model’s judgment.” It’s a path filter in CI — the agent can only touch content/ — and a pull request a human sees first.

When it’s a kid’s site, that PR gate is invisible parental moderation. When in doubt, don’t fight the wave. Bail.

You can’t fight the wave. You’ve got to ride it.

Ride the model’s grain.

The agent writes markdown, never HTML. Its output runs through Pydantic before it touches a file — valid slug, real date, a section that exists.

A narrow output schema is what keeps a cheap model reliable. You’re not wrestling the wave into a shape. You’re giving it a lane and letting it go.

This is what it looks like.

Do less.

Find the seam where AI is genuinely the right tool. Give it that one job. Let honest code carry the rest.

The folder outlives the model.
